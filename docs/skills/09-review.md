# 审稿与后续研究规划

`/review` 根据实际提交的手稿和明确提供的证据作出评价，给出可定位的问题和审稿建议。用户也可以在同一次请求中要求后续研究与论文规划建议。

## 两部分各自回答什么

| 部分 | 回答的问题 | 依据与输出 |
|---|---|---|
| 当前手稿评价 | 问题是否清楚，贡献与证据是否匹配，当前结论能支持到哪里？ | 已提交材料；带文件行号的 findings TSV、定位检查结果和审稿建议。 |
| 可选后续规划 | 下一步值得补什么证据，是否需要缩题或调整，怎样形成论文？ | 已完成的审稿发现，加上用户提供的目标与条件；单独标明的规划建议，设想与当前结果分开。 |

后续规划可以讨论研究价值、现实条件、最小验证、学位论文主线和单篇论文贡献。只展开本次需要的部分，要求不明或材料不足的地方保留待核实；未来可能做成的研究不能算作当前论文已经具有的贡献。

## 如何调用

```text
使用 $review 审查这份手稿，并在最后补充“后续研究与论文规划建议”：
目前最值得继续调查的问题是什么？下一步最小验证是什么？
哪些是修复当前结论必须补的证据，哪些只是可选的后续研究？
```

```text
使用 $review 审查我的论文，保留独立审稿。
审稿结束后，结合我提供的时间和数据条件，分别讨论学位论文主线与单篇论文贡献。
```

普通审稿不会自动生成完整研究计划。希望保存或更新讨论记录时，在请求中写明，后续由 [`/research-plan`](12-research-plan.md) 复用同一份模板和版本保留规则；无须再次批准已经请求的规划工作。

## 独立审稿与作者控制

审查用户自己的手稿时，原有独立审稿流程保持有效：审稿者只接收手稿及明确列出的审稿证据。作者希望以后证明什么、准备怎样转向，以及私人规划条件，不作为该审稿者评价当前论文的依据。

审稿返回后，负责当前对话的助手再结合作者目标提出规划建议，并标明这部分不属于独立审稿结论。方向调整由研究者决定，建议不会自动改写手稿、修改已有计划或联系合作者。

只有想法、尚无手稿时，可直接使用 [`/research-plan`](12-research-plan.md)。不会因缺少手稿而阻止研究讨论，也不会把这种讨论称为已完成审稿。

审稿定位检查验证的是文件和行号，不证明意见正确；规划部分同样是供研究者判断的建议。当前审稿规则见[技能入口](../../.claude/skills/review/SKILL.md)。
